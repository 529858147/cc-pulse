# CC Pulse

Claude Code 会话仪表盘。状态栏显示当前会话的工作状态、缓存倒计时、Token 和上下文；左侧活动栏的 CC Pulse 侧边栏有四个标签页：当前会话、全局洞察、每日活动、模型用量。

全部离线：只读本机 `~/.claude/projects` 下的会话记录，不联网、不读账号凭据、不改 Claude Code 配置。Remote-SSH 下扩展运行在远端，读的是远端的记录。

## 状态栏

| 块 | 内容 |
|---|---|
| 速率 | 始终显示最新一次请求的 tok/s 和缓存剩余时间；轮到你时缓存快过期变黄、过期变灰（Claude 工作中不变色，下一次请求会续期） |
| Token | 本会话（含子代理）总量，请求结束后几秒内显示增量；最近一次请求缓存未命中时变黄 |
| 上下文 | 占用比例和轮数，超过 `contextWarn` 变黄、超过 `contextAlert` 变红 |
| 今日 | 全部会话今天的 Token 和估算费用；悬停看本周、各模型占比，以及缓存写入和缓存读取各花了多少钱。`ccPulse.showToday` 可关 |

## 固定会话与提醒

- **跟随选中的对话标签**：状态栏默认跟随编辑器里当前选中的 Claude Code 对话标签，切到哪个对话，状态栏就显示哪个会话的数据。
  - 标签名按 Claude Code 的规则对应会话标题（超过 25 个字截成前 24 个字加 `…`）；没有标题的会话，标签用的是第一条消息。
  - **新建对话和 `/clear`**：标签叫 “Claude Code”（没有标题）时，状态栏显示“新对话”和全 0 的数据，不再停在上一个会话上。`/clear` 会立刻创建一个只含命令的新会话文件，所以按“标签出现时间附近、由编辑器面板创建、没有被其他标签认领”来找它，不管文件比标签改名早还是晚被发现都能绑上；绑定后你发的消息、之后生成的标题都会跟着走。终端里的会话、别的标签正在显示的会话、被清掉的那个旧会话都不会被误绑。同一个标签里连续 `/clear` 也会重新绑定到最新的会话。
  - 选中的不是对话标签（文件、终端、其他网页视图）时保持上一次的选择；对不上任何会话的对话标签，退回到最近有写入的会话。
  - 对话放在侧边栏而不是编辑器标签里时读不到标签，也是退回到最近有写入的会话。`ccPulse.followTab` 可关闭。
- **固定会话**：优先级高于跟随标签。同一工作区里有多个会话同时在写时，状态栏会跟着最近有动静的那个来回跳。点状态栏提示里的“切换会话”、侧边栏“当前会话”页的按钮，或运行命令 `CC Pulse: 切换会话`，选一个会话固定下来（状态栏图标变成图钉）；选“自动”恢复跟随。固定按工作区记住，会话记录被删除后自动恢复跟随。
- **提醒（默认都关）**：`ccPulse.notifyContext` 在上下文达到 `contextAlert` 时提醒一次（`/compact` 回到 `contextWarn` 以下后可再提醒）；`ccPulse.notifyCache` 在缓存剩不到 1 分钟、且轮到你回复时提醒一次。很久没动静的会话不提醒。

## 请求日志

直接显示在侧边栏“模型用量”页底部（默认全部会话、每页 10 条）。要更宽的视图，点日志标题旁的 ↗、“全局洞察”工具栏的“请求日志”或命令 `CC Pulse: 打开请求日志`，在编辑器里全宽打开（默认当前会话、每页 50 条）。两处各自记住自己的范围、排序和页码。

列：时间、来源（终端 / VS Code / SDK，子代理另行标注）、模型、Effort、成本、未缓存输入、缓存写入、输出、缓存读取、命中率、速度。

- 顶部切换“当前会话 / 全部会话”，再用 今日 / 本周 / 上周 / 近30天 / 全部 限定时间，所属会话在行的悬停提示里。
- 点列标题排序，再点一次反向；每页 10 / 50 / 100 条。
- 缓存未命中（重新写入 ≥ 2 万 token 且命中率 < 50%）的行标黄。

## 时间范围

- **一个范围管三处**：全局洞察、模型用量和它下面的请求日志共用顶部的范围条：今日、本周（周一起）、上周、近 30 天（含今天）、全部，或“按月”（带上一月 / 下一月）。按 `timeZone` 划分。编辑器里全宽打开的请求日志是独立页面，保留自己的范围。
- **每日活动**：卡片固定显示 今日 / 本周 / 上周 / 近30天 / 本月 / 累计，不随范围切换。
- **图表粒度**（天 / 周 / 月）受范围限制：不超过 7 天只能按天，不超过 31 天可按天或周，不超过 92 天三档都可，更长只能按周或月；不适用的档置灰。
- **模型用量**表格按 模型 × Effort 拆行，并给出“成本/次”（费用 ÷ 请求数）和“速度”（tok/s，加权平均）；Claude Code 开始记录 Effort 之前的请求显示“未记录”。范围选“今日”时，用量柱状图和速度趋势按小时（0–23 点）画，数据来自本机仍保留的今天的会话记录。悬停“费用”格可看这一行的费用拆成缓存写入、缓存读取、未缓存输入、输出各多少钱。速度从这一版开始随每日汇总保存，更早的历史没有速度，显示“—”。
- **数据来源不同，别混着比**：模型用量、每日活动来自 CC Pulse 保存的累计历史（含已被 Claude Code 删除的会话）；全局洞察、请求日志来自仍保留在本机的会话记录（默认 30 天）。所以较长范围下两边的请求数会对不上，页面上各自标明了来源。
- 全局洞察里“近 7 天用量”固定 7 天，“活跃会话”表示此刻，二者都不随范围变化。

## 看出异常和花费去向

- **对比**：每日活动的卡片和状态栏“今日”提示会显示变化：今日对比近 7 日日均（今日尚未结束，数字会随时间增长），本周对比上周同期，上周对比上上周，近 30 天和本月对比前 30 天 / 上月同期。基线没被历史完整覆盖时不显示，免得拿完整周期去比残缺周期。涨幅达到一半以上标黄。
- **花费去向**（全局洞察）：按金额拆成缓存读取 / 未缓存输入 / 缓存写入 / 输出。缓存读取占绝大部分 Token，但单价低，占的费用要少得多。下面列出最贵的 5 个会话和 5 个请求，并标出主要花在哪一项。会话页也有同样的费用构成。
- **缓存重写**：一个请求重写了至少 2 万 token 且命中率低于 50%，就算一次缓存重写。按原因归类：隔太久（距上一次请求超过缓存有效期）、切换了模型、压缩后重建（正常，不计入“可避免”）、提示内容变了（其他）。“多花约 $X”是按缓存写入价与读取价的差额估算的。
- **速度**：全局洞察里有按小时的平均速度；模型用量里有按模型的速度趋势（随图表粒度按天 / 周 / 月）。速度从 0.7.0 起随每日汇总保存，更早的天没有。

## 指标口径

- **速率**：输出 token ÷ 请求总耗时。记录里没有首个 token 的时间，所以包含等待首字的时间，比纯解码速度低。
- **缓存倒计时**：从主会话最后一次请求结束开始算，档位（5 分钟 / 1 小时）取自记录里每次请求实际声明的 TTL。子代理的缓存不计。
- **缓存命中率**：缓存读取 ÷（未缓存输入 + 缓存读取 + 缓存写入）。
- **上下文占用**：最近一次主会话请求的输入 + 缓存读取 + 缓存写入，除以 `contextWindows` 匹配的窗口。
- **估算费用**：按 API 价格折算（`pricing.js`，取自 platform.claude.com 定价页，2026-11-24），订阅用户仅作参考。
- **命令执行**：每条管道只算第一个命令，跳过 `cd`、`echo` 等；`coke.sh run <项目> '<PowerShell>'` 拆出实际执行的命令，记作 `coke ▸ 命令`。
- **项目分布**：优先用 `coke.sh run` 的项目名，其次是 `projectRoots` 下被读写最多的一级子目录，否则按启动目录。
- **当前会话**：工作区对应项目目录里最近写入的会话，约每 20 秒重新判断一次。
- **历史**：Claude Code 默认只保留 30 天记录。CC Pulse 把按天、按模型的汇总存在扩展的存储目录（`history-v1.json`），旧记录被删后每日活动和模型用量仍保留。

不提供：套餐额度、首字延迟、上下文按来源的构成。
